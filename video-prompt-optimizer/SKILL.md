# AIGC 提示词写作与优化（视频为主，含前置资产/分镜）

把需求、剧本、分镜、参考片或已有提示词，写成可直接使用的提示词；或把跑坏的结果诊断成最小补丁。
覆盖三个已知视频模型 + 未知模型通用路径，并按 TVC、竖屏短剧、动作、对话情绪、蒙太奇等场景给出不同结构。

## 定位与边界

本 skill 分三层，**输出时仍以模型方言为准**：

1. **场景层**：决定“写什么结构”（TVC、短剧、动作、情绪戏、蒙太奇）。
2. **手艺层**：决定“写得专不专业”（景别、运镜、表演、蒙太奇、一致性、分镜）。
3. **模型层**：决定“模型怎么读”（Seedance 2.0 / 2.5 / Wan 3 / 通用）。

边界：

- 视频提示词为主；角色/场景/道具资产、分镜脚本、剧本改编、视觉规范是**可选前置分支**，不替代视频模型方言。
- 不生成图片/视频、不提交任务、不轮询、不下载。
- 一次只服务一个目标模型；三个模型各写一版时，逐版独立生成。
- 短剧项目内、已有分镜与 REF 槽位时，用 `$short-drama-video-prompts`；本 skill 面向独立任务与多场景写作。
- 不虚构剧情、台词、素材内容；没读到素材就不说“已确认”。
- 不为了“更安全”擅自软化用户的创作意图；高危动作或审核风险只提示并给方案。

## Quick Start

```text
用 $video-prompt-optimizer 写一条 60 秒汽车 TVC，卖“家庭生活方式”
用 $video-prompt-optimizer 把这段小说改成 90 秒竖屏短剧第 1 集，并给 3 镜提示词
用 $video-prompt-optimizer 按超燃动作模板写 30 秒仙侠空战，要 Seedance 2.5
用 $video-prompt-optimizer 优化这条 Wan 3.0 提示词，人物总是变脸
用 $video-prompt-optimizer 同一需求分别写 2.0 / 2.5 / Wan3 三版，分开给
```

**加载上限**：一次最多读 1 份模型方言 + 1 份场景配方 + 1 份手艺参考（跨场景时可叠加第 2 份场景配方，并说明顺序）。涉及排时长、节拍数、一镜装多少信息时，`timing-and-beats.md` 视为必读，不占手艺参考名额；只问一句台词时长时直接看它的 §4，不必再读对话配方。跨场景时先写主场景，再叠加第二场景，并说明顺序。

读的顺序不等于决策顺序：模型可以先锁定，但**模型方言最后读**，避免场景结构被方言语法带偏。

## 工作流与暂停点

每个工作流节点最多停一次：单条最多 1 次；多镜按 B 的四节点（B1 契约 / B2 镜头表 / B3 分批 / B4 成片）停；停完等用户回 `[通过 / 修改 / 自检]`，不连跑。

### A. 单条提示词

1. **契约确认**：复述 1–3 行（模型 / 时长 / 主体 / 关键约束）——“按这个写？”
   - 只有“不可推断项”全部到位（逐字台词 + 说话人、主体数量、素材职责、场景关键项）且 ≤15 秒，才可不停直接写，末尾附【本轮说明】。
2. 写 → 自检 → 交付。

### B. 多镜项目 / 40–120 秒 / 整集

1. **B1 契约确认**（三份契约，见第五步）。
2. **B2 镜头表 / 节拍表 gate**：先给表（镜号/时长/景别/动作/台词/声音/参考），确认后再写逐镜。
3. **B3 逐镜提示词分批**：每批 3–5 镜，批末暂停。
4. **B4 成片 gate**：成片后走诊断入口（见 `iteration-and-diagnosis.md`）。

### C. 诊断 / 迭代

1. 先给**诊断 + 补丁方案**（改 / 加 / 删 / 不动），确认后再动手。
2. 打补丁 → 复测建议。

暂停话术（固定句式）：

> 下一步我会<做什么>；需要你确认<什么>。回「通过 / 修改 / 自检」即可。

用户说“直接给 / 不用确认”时跳过暂停，并在【本轮说明】里注明跳过了哪个节点。

## 第一步：判任务类型

| 任务 | 典型触发 | 输出 |
|---|---|---|
| 写视频提示词 | 给需求/剧本/分镜/参考素材 | 场景结构 + 镜头表（可选）+ 模型提示词 |
| 优化 | 已有提示词，想更好 | 诊断 + 最小补丁 + 完整新版 |
| 诊断 | 已有出片，报“哪一秒/谁/什么坏了” | 归因 + 补丁 + 复测建议 |
| 迁移 | A 模型提示词改 B 模型 | 从需求契约重写 B 版 + 保留/改动对照 |
| 资产 | 角色/场景/道具/修图 | 资产提示词 + 用途 + 一致性检查 |
| 上游 | 小说转剧本、剧本转分镜、视觉规范 | LLM 提示词 + 结构化输出 |
| 多镜项目 | 40–120 秒短片、整集短剧 | Visual Bible + 镜头表 + 逐镜提示词 |

分不清任务类型就问；不要把所有任务都写成“一条 prompt”。

## 第二步：锁目标模型

| 模型 | 别名 | 只读文件 |
|---|---|---|
| Seedance 2.0 | 豆包 2.0、seedance-2.0、2.0 | `references/seedance-2.0.md` |
| Seedance 2.5 | 豆包 2.5、seedance-2.5、2.5 | `references/seedance-2.5.md` |
| Wan 3.0 | 万相 3.0、wan3、wan-3.0 | `references/wan-3.0.md` |
| 其他/未知 | Kling、HappyHorse、MiniMax、Sora 等 | `references/generic-video-model.md` |

**硬规则：没有明确模型就先问，不写最终视频提示词；场景结构/策略/分镜可以先给。** 用户点名的模型优先于下面的推荐；推荐只在用户没指定时使用：

- ≤15 秒、素材少、要 4K → 2.0。
- 15–30 秒、要续写/时间戳/编辑 → 2.5。
- 要 2–5 秒硬分镜、文件/网页参考、线控运镜 → Wan 3。
- 用户点名其他模型 → 通用路径，先问能力/语法，不硬套 Seedance。

用户要“三个模型各写一版”时：A → 写 A → 放；B → 写 B → 放；C → 写 C。每版从需求契约重新生成，不互相翻译。

### 模型能力边界速查

| 模型 | 单次时长 | 时间控制 | 素材上限 | 已知弱项 |
|---|---|---|---|---|
| Seedance 2.0 | 4–15s | 只认镜头序号，不写秒数 | 图 9 / 视频 3 / 音频 3 | 多视图参考易双胞胎；换脸 |
| Seedance 2.5 | 4–30s | 整数秒时间标记，节奏级精度 | 图 30 / 视频 10 / 音频 10（共≤50） | 超长提示词丢约束；末拍被截断 |
| Wan 3.0 | 2–30s | 2–5 秒/段硬骨架 | 图 10 / 视频 5 / 音频 5 | 精确秒数弱；负向词不稳定 |
| 未知模型 | 先问 | 先确认是否支持秒级控制 | 先问 | 不硬套任何方言 |

> 能力随版本变化；关键项目先用 draft / 480p 小样验证，再上正式片。

## 第三步：锁场景（唯一入口）

只决定“写什么结构”，不写模型语法；选定后最后再读命中的模型方言。

| 场景 | 触发 | 配方 | 默认结构 | 关键检查 |
|---|---|---|---|---|
| TVC / 广告 | 品牌片、产品片、卖点、60/30/15 秒、产品登场 | `scenario-tvc.md` | 策略一句话 → 3 创意方向 → 视觉记忆点 → 产品登场 → 品牌落点 | 产品清楚、卖点可证、品牌落地 |
| 竖屏短剧 | 1.5–2 分钟一集、3 秒钩子、结尾悬念、海外短剧 | `scenario-short-drama.md` | 钩子 → 冲突升级 → 转折 → 悬念收尾 | 前 3 秒、单镜 ≤10 秒、结尾想追 |
| 动作 / 打戏 | 30 秒 10 镜、对打、特效、环境破坏、追逐 | `scenario-action.md` | 开场碰撞 → 追击 → 贴身 → 升级 → 终极对拼（追逐见该文件 §3） | 双方区分、攻防可追踪、特效绑定动作 |
| 对话 / 情绪戏 | 双人对白、微表情、站位、反应镜头 | `scenario-dialogue-emotion.md` | 建立 → 反应 → 台词 → 反应 → 落点 | 情绪外化、站位写死、有反应镜头 |
| 蒙太奇 / 节奏 | 平行、交叉、重复、隐喻、空镜、40/60/90–120 秒 | `scenario-montage.md` | 两条线关系 → 镜头并置 → 母题重复 → 落点 | 镜头间是否产生新意义、删线测试 |

### 选场景前先问自己

1. 卖什么 / 讲什么？2. 观众看完记住什么？3. 时长多少？4. 单镜还是多镜、靠什么连接？5. 有无现成资产？6. 目标模型（最后落方言，先不写）。

### 组合规则

| 组合 | 顺序 | 例子 |
|---|---|---|
| 短剧 + 动作 | 先短剧（钩子/冲突/悬念），再动作（打戏结构） | 本集结尾一场打戏 |
| TVC + 蒙太奇 | 先 TVC（策略/产品登场），再蒙太奇（并置/对比） | 60 秒品牌片多线 |
| 情绪戏 + 动作 | 先情绪（关系/潜台词），再动作（冲突爆发） | 对峙后动手 |
| 短剧 + 蒙太奇 | 先短剧（本集结构），再蒙太奇（回忆/对比） | 回忆杀交叉 |

- 主场景决定整体结构；第二场景只处理局部段落。
- 不要把两份节拍表硬拼；先写主结构，再在对应段落标注“这里用动作/蒙太奇写法”。
- 组合超过两个场景时，先拆成镜头段落，逐段路由。

### 没命中 / 模糊时

- 没命中：通用结构 = 主体 + 场景 + 动作 + 运镜 + 光影 + 风格 + 声音 + 约束。
- 只给一句模糊需求：先问“卖什么/讲什么/让观众记住什么”，再问时长与画幅；仍不明确时按 15 秒通用短片写一版并注明假设。
- 只问会改变结构的问题（品牌/剧情？给谁看？单镜还是多镜？有参考片吗？）；风格这类非阻塞项先给默认。

### 交给模型层

1. 确认目标模型与任务类型 → 2. 读命中的模型方言 → 3. 把镜头表翻译成该模型语法 → 4. 用方言检查清单过一遍。
**禁止**：把“钩子/产品登场/平行蒙太奇”这类结构词直接当模型指令。

## 第五步：建立输入契约

按三份契约收集；够就写，不够先问（最多 3 问），可推断的按默认并写明假设。

| 契约 | 收什么 | 不够时怎么办 |
|---|---|---|
| **Brief Contract** | 目标、受众、交付物（条数/时长/画幅/分辨率/声音/字幕）、场景配方、硬约束；TVC 卖点、短剧钩子、动作双方区分、情绪戏潜台词、蒙太奇双线 | 缺目标或交付物 → 问；其余按默认并写明假设 |
| **Direction Contract** | 视觉风格、色调、光影、参考片/参考图、情绪曲线 | 缺风格 → 按题材默认；有参考片 → 先反推再写 |
| **Reference Pack** | 素材清单：编号 / 类型 / 职责 / 不负责什么 | 缺编号或职责 → 问；素材没读 → 不描述 |

按场景追加：

- **TVC**：卖什么、给谁、核心卖点、为什么信、希望什么行动、产品登场时机。
- **短剧**：3 秒钩子、本集冲突、结尾悬念、角色关系、全集时长。
- **动作**：双方视觉区分、武器/能量色、身法对比、环境破坏点、特效边界。
- **情绪戏**：谁对谁、潜台词、站位/距离、反应镜头、台词逐字。
- **蒙太奇**：两条线的关系（因果/并置）、重复母题、空镜功能、声画对位。
- **多镜项目**：Visual Bible、资产清单、镜头表、跨镜一致性锚点。

通用契约仍要锁：

- 主体与数量、事件顺序、结尾状态。
- 台词：说话人、逐字、语言、画内/画外。
- 场景、时间、天气、空间左右/朝向/距离。
- 参考素材：编号、类型、各自负责什么、不得迁移什么。
- 时长、画幅、分辨率、有声/无声、字幕策略。
- 用户明确的“必须/禁止”。

规则：

- **事实来自用户文本；外观只来自可读素材。** 没给的台词不编，没读到的素材不描述。
- **不可推断项**：参考素材职责、逐字台词 + 说话人、主体数量、场景关键项（TVC 卖点、短剧钩子、动作双方区分、情绪戏潜台词、蒙太奇双线）——缺了就问，不猜。
- 每个素材只承担一个主职责；同一素材多职责时拆句写。
- 用户原有措辞若意图正确就保留；只改方言、结构、歧义和冲突。
- 契约确认句只复述 1–3 行，不重抄全文。
- 参数（duration/ratio/resolution）只用于规划节奏，不写进提示词正文；Wan 3 的分镜时间范围、2.5 的时间戳属于创作内容，可以写。
- 现成的输入卡见 `assets/requirement-brief.md`（三份契约）。

## 第六步：写作

顺序：**先结构，后镜头，最后模型方言**。

1. **定场景结构**：按场景配方给出节拍/镜头表/策略一句话；不要直接堆形容词。
2. **排时长**（先读 `references/timing-and-beats.md`）：
   - 先定每镜的拍与信息层数：质感拍附着在叙事拍上；叙事拍 2–3 秒；顺序拍先判**链条式**（整条 3–8 秒）还是**断点式**（拆成动作-反应单元，每单元 2–3 秒）。
   - 用区间表定成片时长：**以信息层数为准**，功能/景别做上限校正、镜头组做下限校正；冲突时信息层数优先（规则见 `timing-and-beats.md` §3）。单镜尽量 ≤15 秒。
   - 台词按“脑内演一遍”估，不用字数硬算；超了拆段、加时长或删句。
   - 模型时间机制（2.0 不写秒数、2.5 时间标记、Wan 3 的 2–5 秒硬骨架）见各自方言，不互相套用。
   - 短剧：3–5 秒/镜，单镜不超 10 秒；空镜 1–3 秒。
3. **锁一致性**：人物/场景/道具资产是否够；不够先补资产或在提示词里写死锚点。
4. **写表演**：情绪外化为眼神、眉毛、嘴角、手部、姿态、呼吸；不要只写情绪词。
5. **写声音**：环境音、动作音、BGM 至少给一句明确态度；不要 BGM → 写“无背景音乐”（2.5 需穷举同义词并在首尾各写一遍）；不要台词 → 写“无台词”。
6. **写约束**：放在模型认的位置；不要散落成互相矛盾的句子。
7. **控长度**：Seedance 中文建议 ≤500 字；Wan 3 硬上限 20,000 字符，但仍以精简为准。
8. **落到模型方言**：最后读命中的模型参考，把结构翻译成该模型能读的语法；场景层不得覆盖模型硬规则。
9. **多镜/批量**：先给镜头表（镜号/时长/景别/动作/台词/音效/参考），再逐镜给提示词；每块自带模型与参数，不拼成一条混合方言。

## 第七步：交付前自检

通用：

- [ ] 全文只有一个模型的方言，没有其他模型的标志性 token。
- [ ] 任务类型与提示词意图一致；编辑/延长/参考没有互相冒充。
- [ ] 主体数量、身份、事件顺序、台词逐字内容与契约一致。
- [ ] 素材编号与上传顺序一致；每个素材一个主职责；没有孤儿引用。
- [ ] 每镜的信息层数 / 拍数与时长匹配（见 `timing-and-beats.md`）；连续动作链算一拍，没有把它当多拍砍断；台词按“演一遍”估算而非字数。
- [ ] 声音层不是空的；BGM 有无已明确；字幕策略已明确。
- [ ] 负向/约束层只写用户明确排除的少量项；不凑数、不重复正向。
- [ ] 没有互斥描述（固定机位 + 环绕、一镜到底 + 硬切、浅景深特写 + 交代全景）。
- [ ] 没有编造事实；没有“我已看过素材”的虚假声明。
- [ ] 没有把参数写进正文。
- [ ] 最后按命中模型参考里的“交付前检查清单”再过一遍。

场景追加：

- **TVC**：有没有策略一句话？产品登场时机对吗？视觉记忆点是什么？品牌有没有落地？
- **短剧**：3 秒钩子够不够？本集冲突有没有升级？结尾有没有悬念？单镜是否超 10 秒？
- **动作**：双方视觉区分够不够？动作是否可追踪？特效是否绑定动作？环境有没有持续破坏？
- **情绪戏**：情绪是否外化？站位/距离是否写死？有没有反应镜头？台词是否逐字？
- **蒙太奇**：镜头之间有没有“新意义”？删掉一条线会不会影响另一条？空镜是否服务剧情？
- **多镜项目**：Visual Bible 是否统一？跨镜锚点是否复用？资产是否齐全？

### 三道验收 gate

1. **结构 gate**（多镜必过）：每镜有目的；信息层数/时长匹配；每场 ≥1 个出彩设计（见 `timing-and-beats.md` §5.1）；镜头表确认后再写逐镜。
2. **提示词 gate**（必过）：上方通用清单 + 命中模型方言的检查清单。
3. **成片 gate**（有回片时）：症状 → 归因四分类 → 最小补丁，不整篇重写。

自检不通过就先改，不要把问题留给用户。

## 第八步：交付

默认格式：

````text
【任务】TVC / 短剧 / 动作 / 情绪戏 / 蒙太奇 / 通用
【模型】Seedance 2.5（单模型，未混用其他写法）
【场景结构】<一句话策略 / 节拍表 / 镜头表>
【建议参数】duration=… ratio=… resolution=… audio=…（参数不进正文）
【提示词】
```text
…
```
【资产依赖】<需要哪些角色/场景/道具参考；缺什么>
【本轮说明】3–5 条：假设、取舍、超限处理
【下一轮先看】1–3 条：最可能出问题的点
````

- 用户只要提示词：只给代码块 + 一行参数。
- 多镜项目：先给镜头表，再逐镜提示词；不要把所有镜头塞进一条 prompt。
- 优化模式在提示词前加：
  ```text
  【诊断】症状 → 根因 → 触发句
  【改动】删 / 改 / 加 / 不动
  ```
- 资产/上游任务：给结构化清单 + 可直接复制的 LLM/图片提示词，并说明下一步交给视频层。

## 不明白时：提问规则

**阻塞问题**（必须问，最多合并成 3 个）：

1. 目标模型/版本不明确（只影响最终提示词；上游结构可以先做），或同时提到两个模型却没说各写一版。
2. 任务类型不明确：参考 / 编辑 / 延长 / 首帧 / 首尾帧。
3. 缺少会改变结果的核心事实：谁说话、逐字台词、主体数量、参考素材职责。
4. 时长超过该模型上限，且没说拆段还是换模型。
5. 场景关键项缺失：TVC 没卖点、短剧没钩子、动作没双方区分、情绪戏没潜台词、蒙太奇没两条线关系。
6. 用户指令互相冲突（15 秒又要 30 秒内容、固定机位又要环绕）。

**非阻塞**（按默认写，并写明假设）：

- 画幅、分辨率、默认时长（16:9 / 1080p / 未指定时按 5 秒起步；模型支持 `-1` 时也可交给模型自选）。
- 默认无字幕。
- 能从题材、上下文、参考素材合理推断的风格与运镜。
- 用户说“你定 / 随便”时的所有非核心项。

提问格式：

```text
写之前确认 2 件事（其余我按默认处理）：
1. 目标模型：Seedance 2.0 / 2.5 / Wan 3.0 / 其他？
2. 这条是「参考生成」还是「编辑现有视频」？
默认：16:9、1080p、有声、无字幕、duration=10。
```

一次问完；用户答完就写；不重复问已回答项；不要把“要不要我继续”当问题。

## 迭代规则

详细流程见 `references/iteration-and-diagnosis.md`。要点：

- **v1 基线**：完整提示词 + 3–5 条【本轮说明】（假设/取舍/超限）+ 1–3 条【下一轮先看】。
- **反馈 → 归因**：提示词写法 / 任务类型或形态 / 参数 / 模型能力边界。
- **最小补丁**：只列改、加、删、不动；不整篇重写。
- **单变量**：一轮只改一个杠杆；多个问题按“身份 > 物理 > 摄影 > 文字 > 声音”排序，或拆轮。
- **版本日志**：v2/v3 记录改了什么、为什么、哪些没动。
- **已验收元素冻结**：用户说“这个可以”的部分，后续不擅自改。
- **复测**：固定 seed、同 duration/ratio、先 draft/480p、best-of-3。
- **停止**：连续 3 轮无改善就停止盲改，要求看成片/截图或缩到一个变量；确认是模型能力边界时明说并给替代路径。
- **迁移**：换模型时保留创作决定，按目标模型参考重写，不逐句翻译。源提示词只用来提取需求契约。

## 与官方 wan3-pe 的关系

吸收其：故事契约、忠于原文、逐素材负责、最小澄清、不替用户扩写剧情、不谎称看过素材、参数与正文分离、单版交付。

区别：本 skill 覆盖三模型 + 通用模型 + 多场景 + 前置资产/分镜；优化时做诊断与最小补丁。

如果用户要“给下游 PE 用的整理稿”，Wan 3 参考里给出官方 wan3-pe 的五段式作为可选中间稿；最终投喂模型仍用七段式公式，两者不混在一份。

## 常见失败模式

| 失败 | 表现 | 修法 |
|---|---|---|
| 场景错配 | 用通用描述写 TVC/短剧/动作，结构不成立 | 先读场景配方，再写 |
| 模型混写 | 2.0 正文出现整数秒；2.5 写 2–5 秒硬骨架；Wan 3 用 `{}` 台词 | 回到单模型参考重写；跑“禁止带入”清单 |
| 资产不足 | 人物/场景没有参考，提示词里硬写“保持一致” | 先补多视图/场景板/站位图，再写视频 |
| TVC 没策略 | 只有画面，没有卖点、目标、行动 | 补策略一句话 + 视觉记忆点 + 产品登场 |
| 短剧钩子弱 | 前 3 秒在铺环境 | 用冲突/异常/强视觉动作开场 |
| 动作廉价 | 特效堆砌、角色串、看不清攻防 | 角色锁定 + 特效绑定动作 + 负面词库 |
| 情绪标签化 | 只写“悲伤/愤怒” | 外化为眼神、眉毛、嘴角、手部、呼吸 |
| 蒙太奇流水账 | 镜头按时间排，没有并置/对比/重复 | 先定两条线关系与母题 |
| 参数进正文 | “16:9、1080p、duration=10”写进提示词 | 移到参数行；正文只留创作内容 |
| 镜头空 / 假循环 | 信息层数不足以铺满时长，模型用循环动作填充 | 砍时长，或补一层信息（见 `timing-and-beats.md`） |
| 连续链被砍断 | 把物理连续的动作用“一拍一动作”拆成几拍 | 连续链算一拍；只在非连续处拆成动作-反应 |
| 一次抛完 | 多镜不给镜头表就直接写逐镜 | 先出表、等结构 gate 通过再写 |
| 契约靠猜 | 关键事实缺失就开写 | 先问（最多 3 问）或写明默认假设 |
| 过度提问 | 什么都问 | 只问阻塞问题；其余给默认 |
| 编台词 | 用户只描述“说了句话”，提示词出现具体台词 | 保留意图描述，或问用户要逐字台词 |
| 整篇重写 | 用户只报一个症状，却把全文换掉 | 用最小补丁；只改触发句 |

## 自测用例（回归）

改完 skill 后，用这 3 条冷读一遍；任何一条不过，先回退再交付。

### 用例 A：单条齐全

输入：「用 Seedance 2.5 写一条 8 秒雨夜追车提示词，3 个动作节拍，台词一句：女主喊“别回头！”」

期望：契约确认 1 行或直接写（不可推断项齐全）；读 场景配方 → timing → 2.5 方言；3 拍各 2–3 秒，短喊话骑拍不增层；交付带【本轮说明】【下一轮先看】。
通过标准：不停在该停处之外；台词位置正确；无 2.0/Wan 3 token。

### 用例 B：多镜缺台词

输入：「把这段 60 秒短剧写成 12 个镜头提示词：雨夜女主追出租车，车里坐着带走她孩子的男人。其它你看着办。」

期望：先问 ≤3 个阻塞项（模型 / 逐字台词 + 说话人 / 交付形态）；先出镜头表（镜号/时长/景别/动作/台词/声音/参考）并暂停；台词列写“待定”，不编；确认后才写逐镜，分批 3–5 镜。
通过标准：不连跑；不编台词；镜头表自带结构 gate。

### 用例 C：诊断反馈

输入：「这版第 3 秒人物脸崩了，后半段动作看不清。」

期望：先给诊断（归因四分类）+ 补丁方案（改/加/删/不动）并暂停；不整篇重写；给复测建议（固定 seed、同参数、先 draft）。
通过标准：先方案后动手；补丁只改触发句。
