# Seedance 2.5 方言

> 适用：`doubao-seedance-2-5-260628`
> 核对：2026-10-30（火山方舟公开文档 + 工作区实测）；2026-10-31 吸收官方 sd25-pe skill 增量
> **只读这一份。** 不要同时读 2.0 或 Wan 3 的参考，也不要把它们的语法带进来。

## 一句话原则

把 2.5 当**视觉内容生产者**，用导演思维写**结构化提示词**：素材指代 → 一句话概述 → 具体情节（时间轴） → 结尾收全局。

> 时长容量、拍的定义、每段该装多少信息，见 `timing-and-beats.md`（模型无关）；本文件只写 2.5 的时间戳机制与方言语法。

## 五条红线

1. 素材只做**指代**，不复述外观；长相、发型、服装由参考图承载。
2. 一个节拍只放**一个可辨识动作**（物理连续链的子相算一拍）；动作优先概括写，只在记忆点写细节，不重复同一动作。
3. 时间轴必须连续，从 0 开始，段间不重叠、不留空；总和 = `duration`。
4. 镜头运动**只在全局写一次**；节拍里只写“此刻运动到哪”。
5. 负向控制只对字幕和音频有明确支持；画面问题优先用**正向锁定**，不要指望负面词表逐条生效。

## 能力边界

| 能力 | 规格 |
|---|---|
| 单次时长 | 4–30 秒（或 `duration=-1`） |
| 参考素材 | 图片 ≤30、视频 ≤10（总长 ≤30s）、音频 ≤10（总长 ≤30s），共 ≤50 |
| 音频单独输入 | 支持，无需配图/视频 |
| 分辨率 | 480p / 720p / 1080p；1080p 为 10bit H.265 |
| 输出格式 | mp4 / **mov**（编辑、延长首选 MOV） |
| 宽高比 | 7 档固定 + `adaptive`；编辑 / 延长 / 首尾帧任务只能 `adaptive` |
| 时间戳 | 响应**整数秒**时间戳 |
| 多视图主体参考 | 支持；>5 主体时建议拆成多张单视图 |
| 语言 | 提示词与台词支持 11 种：中英西印尼马来泰阿葡越日韩 |
| 独有功能 | 白模参考、多宫格分镜、关键帧参考、样片模式（draft，480p）、MOV |
| 提示词长度 | 中文建议 ≤500 字；2.5 能吃更长，但超长会丢约束 |

## 四段式结构

官方原话：**（R2V）素材指代 → 一句话概述 → 具体情节描述 → 结尾补充**。

### 第一段 · 素材指代

素材一多，**映射关系的文字说明比画面本身更重要**。写清三件事：

1. 编号对应（按上传顺序）：`图片1 / 视频1 / 音频1`。
2. 每个素材的分工：谁是形象、谁是音色、谁是动作、谁是场景。
3. 是全参考还是部分参考；部分参考要写参考哪一部分。

推荐句式：

```text
图片1是人物1，对应音频1；图片2是人物2，对应音频2。
图片3是场景，参考图片3的房间结构与材质。
参考视频1的施法动作，视频2的环绕式运镜。
```

两条硬规则：

- 不要把名字写进图片里、再在提示词里直接叫名字——多人场景必混。
- 素材够精准时，只做指代，减少画面复述。写“严格参考视频1的动作与运镜，顺序与视频保持一致”就够了。

> 素材必须用“素材类型 + 序号”引用；`{{Mixed N}}` 这类占位符在送模型前必须换成 `图片N / 视频N / 音频N`。
> 编号写法以平台官方示例为准：本参考默认 `图片N / 视频N / 音频N`（不带 `@`）。若你的平台示例用 `@图片N`，整条统一替换，不要混用。

### 第二段 · 一句话概述

```text
主体 + 地点 + 事件 + 题材/风格 + 特殊运镜
```

例：`雨夜，一名外卖员在老城区骑楼街里躲避三辆追逐的摩托车，一镜到底跟拍，2D 国漫风格。`

### 第三段 · 具体情节

用**时间戳**或“镜头 N”逐段写：画面内容、运镜、动作、台词、音效。
推荐时间戳；每段一个主要动作；具体细节只放在记忆点。

### 第四段 · 结尾收全局

补充贯穿始终的内容：机位/运镜、环境、声音、氛围、排除项。
镜头运动、整体声音要求、负向控制都放这里，不要在每个节拍里重复。

## 时间戳规范

### 三种写法

| 写法 | 示例 | 适用 |
|---|---|---|
| 时间区间 | `0-3秒……3-7秒……7-15秒` 或 `[1s-4s]……[4s-8s]` | 连续段落、慢速运动 |
| 时间点 | `第5s 快速向左横移转场` | 离散触发（切镜、亮相、爆炸） |
| 相对时间 | `她呆滞地站在原地，3秒后周围的人纷纷摇头` | 因果反应 |

### 四条硬规则

1. 时间轴必须连续，不要出现 `0-3秒…5-6秒…` 这种断裂。
2. 区间内剧情太少 → 模型自由发挥；剧情太多 → 过度剪切或遗漏。
3. 不要用时间戳控制频率；“一秒摇头 3 次”这类写法无效。
4. 精度是**节奏级**不是帧级；要卡帧请后期剪。

### 单拍卡与多拍合成

- 总长必须等于 `duration`；最后一个时间标记距结尾至少 3 秒，否则最后一个动作会被截断。
- **单拍卡不用时间标记**：一次生成只写一个连续动作时，不需要 `[0s]` 之类标记；多拍合成一条时才用标记切段。
- **每个时间标记只允许一层发生变化**（主体动作 / 镜头运动 / 光影之一）；同一标记上两层同变，是最常见的“两件都落不了地”的原因。
- 片长与节拍数怎么匹配、一镜装多少信息、台词怎么估时长，见 `timing-and-beats.md`。

## 逐元素写法

### 动作与表情

| 项目 | 2.5 的要求（与 2.0 相反） |
|---|---|
| 动作 | 优先概括性描述：“连续做了几组高抬腿和空翻”“双方展开近身搏斗”；只在少数记忆点写具体细节；不重复写相同动作 |
| 表情 | 写描述性语句，少用成语：“津津有味地吃饭” → “脸上带着满足的笑容，大口地吃饭” |
| 情绪 | 不要把情绪写成眼睛特效；“狂热膜拜”会让瞳孔发光，改成“惊叹”并加“人物眼睛不发光” |
| 节奏 | 一拍只放一个可辨识动作；连续动作链的子相算一拍；非连续的多动词，模型通常只挑一个执行 |

### 镜头语言

- 通识词直接用：景别、运镜、机位、焦段。
- 热门运镜直接写：一镜到底、希区柯克变焦、航拍、FPV、子弹时间、手持、回弹变速。
- 小众专业词拆开：`名词 + 描述性解释`。
- 转场写清触发点与方式：`第5s 快速向左横移转场（向左擦除 + 自然叠化）`。

### 台词

- **推荐稳定写法**：`{角色用中文说：“逐字台词”}`；同一句逐字对白在正文只出现一次。
- 官方指南也接受普通引号 / `角色（情绪）：“…”`；**一个项目选定一种，不要混用**。
- 官方 sd25-pe 句式：`角色（情绪/表达）使用英语说：{逐字台词}`——`{}` 只包台词原文；**语言逐句标注，英语台词易被念成中文，每句都写“使用英语”**，多名说话人分别标注，不要只在开头统一声明。
- 台词只用用户给出的片段：只给了短句/片段就不补写前后句子；只描述说话意图（“用身份压人”“继续争吵”）时不编对白，改用口型、停顿、姿态和对方反应表达。
- 台词后追加语气/表情描述容易诱发字幕；需要时把情绪写在台词前，或另起一句写表演。
- 没有台词时显式写“无对白 / 全片无台词”，并补“人物自然闭口、无旁白、只保留指定环境声”；不需要字幕时写明画面不显示字幕。
- 音色参考：在素材指代段写明 `音频N` 是该角色的音色；在台词句后追加“音色参考音频N”。参考音频可以是预置音色合成或已授权录音；生成后回听确认，不能保证与原音完全一致。

### 声音

- 声音与画面同步生成，不是后期加；把音效挂在有物理接触的节拍上（“靴子踩上碎石”）。
- 音效可用 `<>`，音乐可用 `（）`；保持一种写法。
- 明确不要 BGM 时，穷举同义词（音乐、背景音乐、BGM、配乐、器乐、旋律、氛围铺底音……），并在开头和结尾各写一遍。
- 字幕只有明确开启时才用 `【】`；默认写“无字幕、无对白文字叠加”。

## 参数分离（源自官方 sd25-pe）

画幅、总时长、分辨率、帧率、声音开关是页面/接口参数，只用于规划事件密度，**不写进正文**；用户明确写出的事件时间段属于创作内容，原样保留（见“时间戳规范”）。

## 特殊任务

### 视频编辑

写清**修改范围 + 修改内容 + A→B 的过程**，可配合时间戳做局部编辑。

```text
仅编辑视频1中男人的台词，修改为“你不要过来啊”，口音调整为东北口音，其余内容不要变化。
把视频1中 4-6 秒男人喝咖啡的动作改变为拖地，其余内容不要变化。
```

参数联动：`omni_reference_task_type=edit`、`ratio=adaptive`、`duration=-1`；参考视频 4–30s；提示词里必须出现“编辑视频 / 增加·加上 / 删除·去掉 / 修改·替换·改成”。

### 视频延长

```text
向后延长视频1，<新剧情>，保持角色、场景、画面风格与音效一致。
```

参数：`omni_reference_task_type=extend`、`ratio=adaptive`；关键词“向前/向后延长、延续、续写”；输出格式选 MOV，声画衔接更好。

> 编辑 / 延长任务里直接写 `@视频1`，不要写“参考@视频1”；写成“参考”会被误判成参考任务，时长和画幅就不锁定。（`@` 口径与素材指代段保持一致：同一条内统一带或不带，不混用。）

### 首帧 / 首尾帧

- 优先用参数：`role=first_frame` / `last_frame`，会锁定输出宽高比。
- 也可用 `reference_image` + 提示词指定“图片1为首帧”“图片3为首帧，图片5为尾帧”，但不锁宽高比。
- 两个帧位各占一个图片序号；`@图片N` 按素材出现顺序连续往下数。
- 固定帧用**独立精确句**：`图片1作为首帧。` / `图片3作为尾帧。` 单独成句，不得弱化为“仅作首帧参考/参考开场构图”；紧接一句写该帧定义的构图、主体位置、姿态、道具状态、场景与镜头方向。首帧与尾帧使用相同画幅，避免尾帧被拉伸。

### 白模参考 / 渲染

- 写明白模里参考什么：白模没有光影，只参考运镜和运动；白模有光影且需要，就写参考光影变化。
- 叠加参考图要写对应关系：“将图片1中穿灰色衣服的男人对应视频1中的红色模型”。
- 即使有白模，也要详细描述期望内容，且描述必须与白模吻合。

### 多宫格分镜 / 关键帧

- 多宫格 ≤15 分镜；推荐火柴人/线稿；宫格图不会严格对齐，只是剧情参考。
- 三步写法：① 素材指代 → ② 整体故事梗概 → ③ 按分镜描述并补齐分镜图里没有的信息。
- 关键帧要严格对齐时，第一句写“以图片1至图片7的顺序作为关键帧”。

## 项目级写法（多 CUT / 连续剧集）

当一条提示词服务多个 CUT 或整场戏时，用“制片文档”结构：

1. **素材绑定表**：每行 `图片N ｜ 名称：锁定什么`，只写锁定项，不写画面。
2. **全局固定块**：摄影风格、美术风格、天气氛围、皮肤/材质细节；每块独立成段，可复用。
3. **连续性规则**：哪些必须有、哪些必须没有；例如“只有两组锁链：肩胛骨 + 脚踝；手腕、腰部没有”。
4. **强制控制 + 负向控制**：先正向锁定结构，再给短负面词表兜底。
5. **每个 CUT 的字段表**：`时长 / 景别 / 角度 / 运动 / 焦段 / 位置锁定 / 画面 / 表演 / 台词 / 音效 / 负面控制`。
6. **连续编号**：CUT 14、CUT 15……沿用同一套全局设定。

注意：

- 这种写法很容易超过 500 字建议值；先删不进画面的环境铺陈，保留身份锚点、逐字台词、连续性锁。
- 用 `draft=true`（480p 样片）先验证约束是否生效。
- `{{Mixed N}}` 必须替换成 `图片N / 视频N / 音频N`；纯负面词表只对字幕/音频有明确支持，画面问题以正向锁定为主。
- 同一 CUT 的时长之和要 ≤30 秒；超了就拆两次生成或用延长续写。

## 编译纪律（源自官方 sd25-pe）

- **故事合同**：不改变人物身份与数量、关键道具、场景、事件因果、空间关系和故事结果；素材里更醒目的内容不得顶替文字设定。
- **事实与观察分离**：身份、年龄、关系、结局以用户文字为准；素材只补可直接观察的属性，不把视觉猜测升级为剧情事实。
- **素材逐份负责**：一素材一职、一行一主体（禁止“人物A和人物B参考图片1、图片2”式范围句）；单人设定图不得定义两个同框命名人物；多视角共同定义同一实体时声明“共同定义同一实体、只生成一个实例”。
- **映射优先级**：用户明确指定 > 正文描述 > 素材内容 > 文件名元数据 > 上传顺序；上传顺序只用于稳定编号，不是身份证据。
- **【未采用素材】**：实际可用但未分配职责的素材，逐个列入提示词内并声明不参与（不用于人物/场景/道具/动作/镜头/声音），阻止后续被误激活。
- **触发与反应**：因果揭示镜头先呈现触发原因、再呈现人物反应；原因没被观众看清前，不要过早推成纯面部特写。
- **假装受伤**：剧情是假装/模拟/险些受伤时，保持皮肤、服装、道具完整无伤的可观察状态，不写成真伤口、流血或破损。

## 常见故障 → 修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 情绪一强烈瞳孔就发光 | 情绪被特效化 | 加“人物为正常人眼、不发光，环境光只作用于面部轮廓”；把“狂热/极度震惊”改成“惊叹” |
| 多人物时角色与素材错位 | 上传顺序与出场顺序不一致 | 按人物首次出场顺序上传，并同步改编号 |
| 画面文字拼错 | 字形联想 | 英文拆成独立字母并要求按顺序出现；中文把正确文案做成图当参考 |
| 出现字幕 | 台词后追加语气/表情描述会诱发字幕 | 台词按“角色（情绪）：内容”拆分；仍出现就加“不要字幕” |
| 禁止 BGM 却出现配乐 | 模型换表述绕过约束 | 穷举同义词 + 首尾各写一遍；或后期分离人声 |
| 音频有水波纹噪声 | 提示词里有水/波浪/回音描述 | 移除水、波浪、回音相关描述 |
| 草地/树叶出现指纹状纹理 | 输入图分辨率高于输出 | 输入图分辨率不超过输出分辨率 |
| 任务被判成别的类型、报错 | 提示词意图与参数不匹配 | 显式设 `omni_reference_task_type`；按任务关键词写；编辑/延长用 `adaptive` + `duration=-1` |
| 编辑结果时长变短 | 输出时长自动对齐原视频 | 属正常行为；需要精确时长就改用参考生视频重做 |
| 30 秒片子在 20 秒后连贯性崩 | 节拍数超出时长预算 | 按 `timing-and-beats.md` 减拍，或拆成多条生成再剪 |
| 同图同词，2.0 与 2.5 风格差异大 | 两代模型美学偏好不同 | 要延续 2.0 风格：把 2.0 生成的视频作为 2.5 的延长任务输入，输出 MOV |

## 交付前检查清单

- [ ] 素材指代是否写成“图片N / 视频N / 音频N”，且与上传顺序一致？
- [ ] 人物/产品是否只描述一次（后面不再重复外观）？
- [ ] 时间轴是否连续、没有跳段？总和是否 ≤30 秒且等于 `duration`？最后一个标记距结尾是否 ≥3 秒？
- [ ] 每拍是否只承载一个可辨识动作、信息层数是否在 `timing-and-beats.md` 的区间内？
- [ ] 是否每个时间标记只变一层（主体/镜头/光影）？单拍卡是否没有多余的时间标记？
- [ ] 一拍是否只给一个可辨识动作？（连续链的子相算一拍，不要按动词数硬拆）
- [ ] 镜头运动是否只在全局写一次？
- [ ] 声音要求（无 BGM / 只要环境音）是否在开头和结尾都写了？
- [ ] 负面控制是否只用在字幕和音频上？画面问题是否已改成正向锁定？
- [ ] 编辑/延长/首尾帧任务的参数是否按锁定规则配置（`adaptive` / `-1` / 关键词）？
- [ ] 关键帧任务是否在第一句写明“以图片X至图片Y的顺序作为关键帧”？
- [ ] `{{Mixed N}}` 是否已全部替换？

## 禁止从 2.0 / Wan 3 带入

- 2.0 的“每次提到主体都重复外观描述”：2.5 仍可用 `图片N` 指代，但不要复述长相、发型、服装，只写职责与动作。
- 2.0 的逐帧肢体拆解、低缓小动作偏好：2.5 用概括动作 + 记忆点细节。
- 2.0 的“不写时间戳”习惯：2.5 认整数秒时间戳。
- Wan 3 的七段式结构、`图1` 指代、`说道：“…”` 台词语法、2–5 秒硬分镜骨架。
- Wan 3 的“负向清单独立成块”作为主要画面控制手段：2.5 画面问题靠正向锁定。
