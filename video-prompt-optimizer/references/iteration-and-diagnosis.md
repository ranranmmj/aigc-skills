# 迭代与诊断

> 通用手法，**不写任何模型的专属语法**。模型方言只从命中的那一份模型参考里取。
> 与模型参考冲突时，以模型参考的硬规则为准。

## 1. 迭代目标

不是“每轮重写一版”，而是：

1. 先确认**这一版哪里不对**；
2. 找到**最可能的原因**；
3. 只改**一个变量**；
4. 让下一版比上一版更接近验收。

整篇重写通常会让上一轮已经对的部分一起漂掉，尤其是人物一致性、空间关系、声音层。

## 2. 版本与验收契约

每轮维护三样东西：

- **v1 基线**：完整提示词 + 建议参数 + 本轮假设。
- **已接受项**：用户明确说“可以 / 对 / 就这样”的部分。
- **待修项**：按优先级排序的问题清单。

规则：

- 已接受项默认冻结；用户没要求就不改。
- 用户改变创作意图（不是 bug）时，作为新基线处理，不当作补丁。
- 每轮输出都带上“改了什么 / 为什么 / 没动什么”。

## 3. 反馈采集

用户只说“不好看 / 不对”时，先问最少的信息：

1. **第几秒**（或哪个镜头/哪一段）。
2. **谁/什么**（哪个角色、道具、场景）。
3. **发生了什么**（实际看到什么）。
4. **期望是什么**。
5. 是否**每次都有**，还是偶发；seed、duration、ratio 是否有变化。

没有这些信息时，不要靠猜整篇重写。可以给一个二选一/三选一的诊断问题，例如：

> 这版最想先修的是：人物一致性 / 动作节奏 / 镜头运动 / 声音 / 画面文字？其余我先不动。

## 4. 归因四分类

| 归因 | 典型表现 | 处理 |
|---|---|---|
| 提示词写法 | 指令歧义、互相矛盾、漏写关键层、复述了不该复述的 | 改触发句；补/删/换一个局部 |
| 任务类型或形态 | 编辑被写成参考、延长被写成重生成、首帧与参考混用 | 先改任务声明与素材组合，再改正文 |
| 参数不匹配 | 时长/画幅/音频/任务类型参数与意图不一致 | 先改参数，再决定正文是否要动 |
| 模型能力边界 | 物理交互穿帮、精细手部、极端运镜、文字生成 | 明说“这不是提示词能解决的”；给替代路径（拆段、换视角、换形态、后期） |

**先归因，再改。** 归因错了，补丁越多越乱。

## 5. 症状 → 杠杆

| 症状 | 先查什么 | 常见杠杆 |
|---|---|---|
| 人物换脸 / 不一致 | 参考图质量、编号、是否复述外观 | 换清晰参考；按类型编号；删掉外观复述；固定 seed |
| 双胞胎 / 多出一个人 | 人数是否写死、参考图是否过多 | 明确人数；单人单图；分组；加一致性约束 |
| 台词截断 | 字数是否超过时长容量 | 按约 4 字/秒估算；拆段；加时长；删句 |
| 口型不齐 | 是否写了口型同步、音色参考位置 | 补口型指令；音色参考与说话动作同句；生成后逐镜核对 |
| 动作太快 / 太慢 | 一个节拍塞了几个动作 | 一节拍一动作；调整时长；写清起止状态 |
| 运镜乱 | 是否一镜多运镜、主体动作与镜头动作混写 | 一镜一运镜；固定机位与主体动作分开写；别过度矫正 |
| 字幕乱入 | 是否显式禁字幕、参考图是否带字 | 写“画面干净无字幕叠加”；修参考图；后期裁切 |
| BGM 乱入 | 声音层是否空着 | 写“无背景音乐”；首尾各写一遍；穷举同义词 |
| 风格漂移 | 风格是否只在开头提了一次 | 风格写进全局；参考图与目标风格一致；必要时转风格图 |
| 空间 / 朝向错 | 是否写死左右、朝向、距离 | 位置 + 朝向 + 距离；躺卧写头脚方向；≥3 人先分区 |
| 道具握反 / 朝向乱 | 是否用相对方位描述 | 用功能命名；两端都给方向；写握姿；结尾加一致性声明 |
| 任务误判 | 提示词意图与任务声明是否一致 | 先改任务声明与关键词；参数同步；编辑/延长不要重述全片 |
| 跨镜漂移 | 上一镜结束状态是否等于下一镜开始状态 | 每段写结束状态；下段从结束状态起；固定 seed；跨镜一致性声明 |
| 过度矫正 | 修一个问题时把另一个正确行为锁死 | 只改触发句；把“镜头固定”和“主体动作幅度”分开写 |
| 审核拦截 | 是文本层拦截还是画面层拦截 | 文本层软化触发词或告知用户；不要用画面补丁治文本拦截 |

## 6. 最小补丁格式

```text
【诊断】症状 → 根因 → 触发句
【改动】
  改：<原句> → <新句>
  加：<新增句>
  删：<删除句>
  不动：<明确保留的句子/参数>
【完整提示词】<新版全文>
【复测】seed=… / duration=… / ratio=…；看 <具体观察点>
```

原则：

- 能改一句就不改一段；能改一段就不重写全文。
- 一次只改一个杠杆；多个问题按“身份 > 物理 > 摄影 > 文字 > 声音”排序，或拆轮。
- “不动”要写出来，防止下一轮又被改掉。
- 补丁必须能解释“为什么这样改会改善症状”。

## 7. A/B 复测纪律

- **单变量**：一轮只动一个变量；同时改提示词和参数，无法判断是谁起效。
- **固定条件**：同 seed、同 duration、同 ratio、同 resolution、同参考素材。
- **先小后大**：能用样片/低分辨率验证就先验证，再跑正式片。
- **best-of-3**：同条件跑 3 次挑最好，避免把偶发当规律。
- **记录**：每轮记下版本、改动、参数、结果；没有记录就无法复现。
- 平台不暴露 seed 时，至少固定其余参数，并说明“无法完全复现”。

## 8. 停止条件与能力边界

停止盲改的信号：

- 用户已验收。
- 连续 3 轮同一问题没有改善。
- 每轮都在改不同地方，但没有一个变量被单独验证。
- 症状落在模型明确弱项（剧烈物理交互、精细手部、极端运镜、复杂文字）。
- 成本/时间已超过用户预期。

此时：

1. 停止整篇重写。
2. 要求看成片/截图，或让用户描述具体时间点。
3. 缩到一个变量做一次干净复测。
4. 如果确认是能力边界，明说：

> 这个症状更像模型能力边界，不是提示词写法问题。继续加约束可能只会让画面更僵。  
> 三个替代路径：① 拆段/换视角；② 换形态或换模型；③ 后期修。你选哪个？

不要用无意义的补丁堆砌来假装解决。

## 9. 版本日志模板

```text
v1  基线：<一句话>；假设：<…>；待看：<…>
v2  改动：<改/加/删>；原因：<…>；未动：<…>；复测：<结果>
v3  改动：<…>；原因：<…>；未动：<…>；复测：<结果>
```

日志只记必要信息，不写成长篇分析；但“未动”和“复测结果”不能省。

## 10. 常见误修

| 误修 | 为什么错 | 正确做法 |
|---|---|---|
| 整篇重写 | 把已对的部分一起改漂 | 最小补丁；只改触发句 |
| 堆形容词 | 不解决结构问题，还稀释指令 | 先查任务/结构/参数，再考虑措辞 |
| 堆负向 | 负向互相稀释，且否定词不稳定 | 只留少量（Wan 3 建议 3–8 项）；先消正文矛盾；能正向就正向 |
| 同时改参数和提示词 | 无法归因 | 一次只动一个变量 |
| 把创作意图当 bug | 用户要的运镜/尺度被“修正”掉 | 先分清模型 bug 与用户意图 |
| 擅自软化 | 改掉用户要的暴力/亲密/风格 | 提示风险 + 给方案，由用户决定 |
| 只改措辞不改形态 | 编辑任务写成参考，怎么改都不对 | 先改任务类型与素材组合 |
| 忽略声音层 | 有声模型自配 BGM/旁白 | 显式写声音；不要就写“无台词/无背景音乐” |

## 11. 跨模型迁移

把 A 模型提示词改成 B 模型时：

- **保留创作决定**：主体、事件、台词、参考素材职责、时长意图、风格、已验收的表演。
- **不保留语法**：结构、时间控制方式、台词语法、声音符号、负向策略、参数名。
- **不逐句翻译**：按 B 模型参考从需求契约重写；逐句翻译最容易把 A 的方言带进 B。
- 输出时给一张对照：

```text
保留：<主体/事件/台词/参考职责/风格>
改写：<结构/时间控制/台词写法/声音层/负向>
注意：<B 模型的互斥规则、上限、参数联动>
```

迁移后按 B 模型的检查清单重新自检；不要用 A 的清单验收 B。
